# Delivery Tracking

Transportation service is responsible for populating shipment tracking information.

For this purpose, Stord has partnered with [Shipium][shipium-docs].
Shipium is a TMS platform that helps B2C shippers deliver orders on-time and at the lowest cost through their rate shopping, label printing capabilities, and shipment tracking capabilities.

## Registering Shipments

In order to receive tracking information from Shipium for a shipment,
its label has to have been generated by Shipium, or it has to be
registered.

To register shipments, Facility Activity Service, makes an API call to Parcel Service registration endpoint via `ParcelClient.create_registration`. See: [Shipment Registration][shipment-registration]

## Collecting Tracking Information

Relevant modules:

* `TransportationService.DeliveryTracking.ParcelTrackingWorker`.

We get delivery tracking events via kafka messages from Parcel Service and update the status 
of shipments based on the response. We also persist `TransportationService.TrackingEvents`.

[shipment-registration]: https://parcel.stord.engineering/api_docs.html#/shipment_registrations/registrations.create

## Shipium Client

`TransportationService.Clients.Shipium` is the module interfacing the Shipium API.

To make calls in development, set `SHIPIUM_API_KEY` in your `.env` using
the value from [1Password](https://my.1password.com/vaults/35aplwiel27phehagqbsf3phmm/allitems/zyxkiyxq4sfwymopawi7apbfjy).

## Eventing

The flow for receiving transportation-order and order-shipment information is
two-fold. We receive a kafka event on `facility_activities` that notifies this
service about a new order/outbound. It used to be the case that services would
make an HTTP POST to transportation service to create these transportation
orders. We also
receive POSTs [from other
services](https://app.datadoghq.com/apm/traces?query=env%3Aproduction%20AND%20service%3Atransportation-service%20AND%20operation_name%3Aopentelemetry_phoenix.server%20AND%20resource_name%3A%22POST%20%2Fv2%2Fshipments%22&cols=core_service%2Ccore_resource_name%2Clog_duration%2Clog_http.method%2Clog_http.status_code&historicalData=true&messageDisplay=inline&sort=desc&spanType=all&spanViewType=logs&start=1682379853203&end=1682383453203&paused=false)
(mostly from facility-activities-service) that inform us about new shipments.

> what is a *blind receipt*? you can have a shipment get created _before_ any
> system in stord knows about the order to which that shipment(s) belongs. this
> create_shipment takes place over HTTP, not kafka. we can expect a kafka event
> from facility_activities that has `order_shipment_ids` already on it. this
> means that we have to associate those shipments (which already existed, and
> are "the blind shipments/receipts") back onto a transportation order.

We create a transportation order via eventing in the following flow:

1. a kafka event on the facility activity topic is received
2. we match for "action: create" as well as [a few more fields](https://github.com/stordco/transportation_service/blob/b1a7109dac4c07d78b8fe38d81abbf600c77a342/lib/transportation_service/message_handler.ex#L213-L221) implicitly
3. a `transportation_order` is created if all the necessary fields exist, and
   inserted. a TO is simply an abstraction entity that associates (possibly
   many) shipments on that order, with important insertion timestamps. here's an

We also want to use eventing to notify other parts of our system about delivery
tracking updates. For now, this includes publishing events at the end of our
oban (cron) job:
`TransportationService.DeliveryTracking.ParcelTrackingWorker`. 
This worker processes delivery tracking events from Parcel Service by finding  
the shipment an event belongs to, updating the shipment status and enqueuing 
the event to `CreateTrackingEventsWorker`.

tl;dr:

When a new order shipment [tracking_event is
created](https://github.com/stordco/transportation_service/blob/b1a7109dac4c07d78b8fe38d81abbf600c77a342/lib/transportation_service/delivery_tracking/create_tracking_events_worker.ex#L17)
from Parcel Service, we queue up a worker to emit the full details of that shipment and
its associated/known tracking_events. This will be a little spammy, but that's
better than the alternatives.
